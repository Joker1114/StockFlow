# 酒水箱码、散瓶与供应商规则

本规则由 2026-11-17 的需求确认产生，覆盖旧版 SDD 中“不做包装换算”和“酒水一物一码每码计一件”的描述。

## 库存口径

- 酒水最小单位为**瓶**。每款物资维护 `bottles_per_box`，默认 6 瓶，后续修改只影响新入库的箱；已入库箱的容量保留入库时快照。
- `stock_qty` 是总瓶数；`loose_qty` 是**未绑定箱码的散瓶数**；箱码下的 `remaining` 是该箱尚存的瓶数。始终满足：`stock_qty = loose_qty + 所有该物资箱码 remaining 之和`。
- 酒水统一使用“箱码＋散瓶”流程，不再由操作员选择扫码模式。每扫一个不同箱码生成一条独立箱记录；同一物资可在同一张入库单中同时录入多箱和散瓶。旧数量模式酒水的历史余额保留为散瓶。
- 供应商由管理员维护。所有新入库单必须选择有效供应商，单据保存当时的供应商名称快照。旧单据允许没有供应商。

## 入库

每个新箱码按该物资当前的每箱瓶数增加库存，并保存该箱容量与剩余瓶数。仍有剩余库存的箱码不能再次入库；同一单据中同一码不能重复扫描。已完全出库的同物资箱码可再次入库，按本次每箱瓶数建立新一轮库存。散瓶按实际瓶数增加 `loose_qty` 与 `stock_qty`，但**每张入库单中每款物资的散瓶数必须严格小于其每箱瓶数**，例如每箱 6 瓶时可录入 0–5 瓶散瓶。前端即时提示，服务端保存时再次校验。全部在一笔 SQLite `BEGIN IMMEDIATE` 事务内提交。

开单页先选择物资，再点“相机连扫”。扫码窗口保持开启，每识别一个不同的码就加入当前物资行；再次识别同一码会提示重复。点“结束扫码”后回到单据，核对数量再保存。App 使用 5+ Barcode 控件，浏览器 H5 使用摄像头连续识别；H5 摄像头需要 HTTPS 或 localhost。可随时手动粘贴码值识别。

## 出库

- 普通出库单必选领用公司，下拉列表来自组织机构中的已启用子公司。保存单据时记录所选公司和当时的名称。
- 扫箱码后显示该箱当前剩余瓶数。本次可出 1 到剩余瓶数，默认填满当前剩余量。部分出库后，余瓶**仍绑定原箱码**，下一次继续扫同一码出库。箱码余量为 0 后不能继续出库。
- 未扫箱码的散瓶出库只扣 `loose_qty`，数量不得超过散瓶库存。箱码内余瓶不会自动转为散瓶库存。
- 一张出库单可混合箱码出库与散瓶出库。任一箱余量或散瓶库存不足，整张单拒绝，所有余额不变。

## 退库与库存调整

- 退库必须从一张已保存的普通出库单发起，填写退库原因。每款物资、每个箱码或独立编码只能退回该原单尚未退回的数量；散瓶退回散瓶库存，箱码内退回原箱码，且不能超过原箱容量。退库单保存后关联原出库单，不能用普通采购入库代替。
- 库存调整可由任何已登录用户发起，选择增加或减少并填写原因。酒水可分别调整散瓶或指定箱码，增加箱码库存不得超过箱容量，减少不得超过当前余量。新发现的箱可在增加调整中录入新箱码。调整单记录物资、数量与调整原因。
- 普通采购入库的散瓶数仍须小于每箱瓶数；库存调整为了反映盘点事实，不受这项入库余瓶上限约束。

## 接口数据

入库示例（同一款酒两箱加三瓶散瓶）：

```json
{
  "request_id": "1cf7f3cb-c78b-45a5-9602-f85db054e080",
  "direction": "IN", "supplier_id": 1,
  "items": [{"product_id": 7, "loose_quantity": 3,
    "boxes": [{"code_value": "BOX-001"}, {"code_value": "BOX-002"}]}]
}
```

调用 `GET /api/companies` 获取可选的领用公司。以下出库示例从已扫的箱码出两瓶，再从散瓶出一瓶。

```json
{
  "request_id": "94e1a35b-0ec0-4d67-9773-a90568646620",
  "direction": "OUT", "recipient_company_id": 1,
  "items": [{"product_id": 7, "loose_quantity": 1,
    "boxes": [{"code_value": "BOX-001", "quantity": 2}]}]
}
```

`quantity` 可不传，服务端根据箱码和散瓶计算总瓶数；若传入则必须一致。`GET /api/products` 返回总瓶数、散瓶数、完整箱数、已开箱数及箱内余瓶；`GET /api/boxes?product_id=...` 分页列出仍有余瓶的箱码。`POST /api/scan/resolve` 对已登记箱码返回当前容量和剩余瓶数。供应商接口为 `GET/POST /api/suppliers`、`PATCH/PUT /api/suppliers/{id}`。

退库前调用 `GET /api/documents/{原出库单ID}/returnable` 获取每款物资、每个箱码剩余可退数量。提交 `POST /api/documents` 时传 `kind: "RETURN"`、`direction: "IN"`、`source_document_id`、必填 `remark` 及本次退回的 `items`。库存调整通过同一提交接口传 `kind: "ADJUST"`、增减方向 `IN`/`OUT`、必填 `remark` 及调整明细。单据列表可用 `kind` 筛选。

## 旧数据迁移

数据库启动时自动增加新字段和箱码表。旧酒水数量模式余额迁为散瓶，后续将其物资模式统一为箱码流程，不改库存数量或历史单据。旧酒水序列码在库余额按旧计量口径保留为“每码容量 1”的历史箱记录；新入库箱使用物资设置的每箱瓶数。若旧酒水已有库存且旧单位不是“瓶”，启动会明确报错，避免猜测换算比例；需先在备份副本中人工核对后迁移。当前本地 Docker 数据升级前已生成一致性备份。
